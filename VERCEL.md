# Vercel configuration

Everything here is either set in `vercel.json` (committed, applies on the next
deploy) or in the Vercel dashboard (not in the repo — someone has to click it).
The dashboard items are listed because they are invisible from the codebase and
two of them are load-bearing for SEO.

---

## ⛔ NEVER ADD AN SPA REWRITE

```jsonc
// DO NOT ADD THIS
"rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
```

This is the standard Vite/React SPA config and it would **silently destroy the
SEO of all 64 routes**. Every URL would be served the HOMEPAGE's HTML — its
title, its canonical, its OG card, its JSON-LD — and React would then hydrate
and client-route to the right page, so **the site would look completely correct
to a human being**. Only crawlers would see it, and they would see one page
repeated 64 times.

Vercel resolves `dist/about/index.html` at `/about` natively. The rewrite is not
needed and never was. CLAUDE.md records the same failure from `npx serve -s` and
`vite preview`; on Vercel it would be live.

## Dashboard — has to be done by hand

### 1. ⛔ Primary domain: apex, not www

**Status: NOT DONE. This is the highest-value item on the list.**

The site currently serves from `www.thinkorange.in`, and `thinkorange.in`
308-redirects to it. But the codebase declares the **apex** everywhere — all 64
canonicals, all 64 `og:url` tags, every `<loc>` in `sitemap.xml`, the `Sitemap:`
line in `robots.txt`, and every JSON-LD `@id`. So every page is *served* at one
host while *declaring* the other as canonical, and that canonical immediately
redirects back.

Fix in **Settings → Domains**: make `thinkorange.in` the production domain and
let `www` redirect to it. **No code change is needed** — the whole site already
says apex.

> If you would rather keep `www`, do NOT simply edit `site.domain` in
> `src/content/nav.js`: `Footer.jsx` renders that field as the visible link
> text, so the footer would start printing "www.thinkorange.in". Add a separate
> `site.origin` and point the five `ORIGIN` constants (`seo.js`, `jsonld.js`,
> `RootLayout.jsx`, `prerender.mjs`, `finderUrl.js`) at it instead.

Whichever you pick, both hosts must be claimed in Search Console.

### 2. Deployment Protection

**Settings → Deployment Protection.** Confirm preview deployments are not
publicly indexable. Vercel sets `X-Robots-Tag: noindex` on preview URLs by
default; a crawlable `*.vercel.app` preview is a complete duplicate of the site.

### 3. Build settings

Framework preset **Vite**, output `dist`. Nothing custom is needed: `postbuild`
runs `scripts/prerender.mjs` automatically after `vite build`, and that is what
writes the 64 static pages, the redirect stubs, `sitemap.xml`, `robots.txt` and
`llms.txt`. ⚠️ If the build command is ever overridden to bare `vite build`,
**`postbuild` is skipped and the site ships as an unprerendered SPA** with one
shared `<head>`. Same blast radius as the rewrite above.

### 4. Search Console / Bing

Not a Vercel setting, but it belongs on the same checklist: add the property (a
Domain property via DNS covers apex and www at once), submit
`https://thinkorange.in/sitemap.xml`, and do it the same day the domain decision
in §1 lands so the migration is visible.

## `vercel.json` — what each block is for

### `trailingSlash: false`

`/about` and `/about/` both returned 200 — two URLs, one page. This 308s the
slashed form to the clean one, which is what the canonicals and the sitemap
already say.

### Cache headers

Vercel's static default is `public, max-age=0, must-revalidate` on everything,
including content-hashed bundles. That was making every repeat visitor
revalidate every JS, CSS and font file on every page load.

| Path | Policy | Why |
|---|---|---|
| `/assets/*` | 1 year, `immutable` | Vite content-hashes these (`react-0T9Avz-T.js`). The name changes when the bytes change, so it can never go stale. |
| `/fonts/*` | 1 year, `immutable` | Stable filenames, self-hosted, and they do not change. |
| `/icons/*` | 1 week | Stable names but NOT hashed — generated by `scripts/icons.mjs`. A week caps how long a redrawn mark could linger. |
| `/og/*`, `/images/*` | 1 hour + SWR | ⛔ **Deliberately NOT immutable.** These filenames are stable and the files are *regenerated on every build* — `og-images.mjs` rewrites all 64 cards each time. Marked immutable, a corrected OG card or a replaced photograph would be stale in browsers for a year with no way to bust it, because there is no hash in the name. |

### Security headers

`nosniff`, `Referrer-Policy` and `X-Frame-Options` are Lighthouse Best-Practices
items and cost nothing. `SAMEORIGIN` is safe here: the Google Maps embed makes
*us* the parent frame, so it is unaffected.

⚠️ **No CSP, on purpose.** The site loads GA4, a Google Maps iframe and Google
Fonts. A CSP written without testing each of those will silently break one of
them, and the failure mode is a blank map or dead analytics that nobody notices
for a month. Worth doing later, deliberately, with the preview deploy open.
